# Releasing and packaging

English | [한국어](RELEASING.ko.md)

## Versioning

[Semantic Versioning](https://semver.org). Tags are `vMAJOR.MINOR.PATCH`.

- `0.x`: pre-1.0, breaking changes allowed in minor releases (documented in CHANGELOG).
- Patch bump per merged change; tag and publish a GitHub Release at each new minor.
- Pre-releases use `-rc.N` (e.g. `v0.2.0-rc.1`).

## Release flow

1. Merge to `main` with CI green.
2. Update `CHANGELOG.md` ([Keep a Changelog](https://keepachangelog.com) format).
3. Push an annotated, signed tag: `git tag -s v0.2.0 -m "v0.2.0" && git push origin v0.2.0`.
4. GitHub Actions runs GoReleaser: builds linux/darwin/windows × amd64/arm64 (`.tar.gz` for Linux/macOS, `.zip` for Windows), creates archives, checksums, SBOM, cosign signature, provenance, and the GitHub Release.

## Distribution channels

| Channel | Notes |
|---------|-------|
| GitHub Releases | Source of truth for binaries |
| Homebrew tap | `brew install <owner>/tap/<name>` (generated by GoReleaser) |
| krew | Plugin manifest for `kubectl <name>`; the binary is named `kubectl-<name>` |
| Container image | Distroless, nonroot, published to GHCR, signed |
| `go install` | Supported for developers |
